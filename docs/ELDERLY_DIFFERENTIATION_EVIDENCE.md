# BITBOX 고령층 특화 차별성 근거 자료

> 작성 목적: 한이음 개발보고서, 작품소개서, 발표자료에서 BITBOX의 고령층 특화 필요성과 차별성을 과장 없이 설명하기 위한 근거 문서

## 1. 한 문장 포지셔닝

**BITBOX는 일반 지도 앱의 기능을 축소한 서비스가 아니라, 디지털 조작에 어려움을 겪는 고령층이 큰 글씨와 음성만으로 실시간 버스 정보와 목적지 경로를 안전하게 확인하도록 설계한 고령친화형 대중교통 키오스크다.**

핵심 차별화 공식은 다음과 같다.

`실시간 교통 데이터 + 고령친화 다중감각 인터페이스 + 오안내 방지 안전확인`

## 2. 왜 필요한가: 공신력 있는 근거

### 2.1 초고령사회에 대응하는 공공 교통 인터페이스

- 국가데이터처의 「2025 고령자 통계」에 따르면 2025년 국내 65세 이상 인구는 전체의 **20.3%**이다.
- 고령인구 비중은 2036년 30%, 2050년 40%를 넘어설 전망이다.
- 2024년 65세 이상 고령자의 인터넷 이용률은 76.9%로, 고령층도 디지털 서비스를 실제로 이용하는 집단이다.

해석: 고령층을 디지털 서비스 밖에 있는 집단으로 볼 것이 아니라, 디지털 서비스를 사용하지만 접근 가능한 인터페이스가 필요한 대규모 사용자층으로 봐야 한다.

출처: [국가데이터처, 2025 고령자 통계](https://kostat.go.kr/board.es?act=view&bid=10820&list_no=438832&mid=a10301060100)

### 2.2 문제는 기기 접근보다 조작 역량에 더 가깝다

한국지능정보사회진흥원(NIA)의 「2025 디지털정보격차 실태조사」는 일반국민의 수준을 100으로 두고 고령층을 비교한다.

| 지표 | 고령층 전체 | 70대 이상 |
|---|---:|---:|
| 디지털정보화 종합 수준 | 71.8% | 53.6% |
| 디지털정보화 접근 수준 | 95.4% | 90.7% |
| 디지털정보화 역량 수준 | 56.2% | 29.4% |
| 디지털정보화 활용 수준 | 75.6% | 51.8% |

해석: 70대 이상도 기기·인터넷에 접근할 수 있는 수준은 90.7%이지만, 실제 조작 역량은 29.4%에 그친다. 따라서 앱 설치나 기기 보급만으로는 부족하고, **입력 단계와 정보 구조 자체를 단순화한 인터페이스**가 필요하다.

출처: [NIA, 2025 디지털정보격차 실태조사 보고서](https://nia.or.kr/site/nia_kor/ex/bbs/View.do?bcIdx=29168&cbIdx=81623&parentSeq=29168), 보고서 21·25·84쪽

### 2.3 기존 키오스크에서 실제로 발생한 불편

한국소비자원의 고령소비자 키오스크 조사에서는 다음 불편이 보고됐다.

- 복잡한 단계: 51.4%
- 다음 단계 버튼을 찾기 어려움: 51.0%
- 그림·글씨가 잘 보이지 않음: 44.1%
- 관찰조사에서 70세 이상 참여자 5명 중 3명은 버스터미널 발권을 중간에 완료하지 못했다.
- 같은 70세 이상 참여자 5명 모두 패스트푸드점 주문을 완료하지 못했다.

주의: 마지막 두 결과는 키오스크 이용 경험이 없는 서울 거주 65세 이상 10명을 대상으로 한 소규모 관찰 결과이므로 전체 고령층의 비율로 일반화하지 않는다. 다만 복잡한 절차, 낯선 용어, 작은 글씨, 시간 압박이 실제 이용 장벽이 될 수 있음을 보여주는 사례로 사용한다.

출처: [한국소비자원, 고령소비자 비대면 거래 불편 조사](https://www.kca.go.kr/kca/sub.do?menukey=5084&mode=view&no=1002988750&page=48)

## 3. 접근성 표준과 BITBOX 설계의 연결

W3C는 고령 사용자에게 시력·미세 운동 능력·청력·단기 기억과 집중력 저하가 디지털 과업 수행의 장벽이 될 수 있다고 설명한다. 또한 고령층 요구의 상당 부분은 기존 웹 접근성 표준으로 대응할 수 있다고 정리한다.

출처: [W3C WAI, Older Users and Web Accessibility](https://www.w3.org/WAI/older-users/)

WCAG 2.2의 관련 기준은 다음과 같다.

- 일반 텍스트 명암비 최소 4.5:1, 큰 텍스트 최소 3:1
- 콘텐츠나 기능 손실 없이 텍스트를 200%까지 확대 가능해야 함
- 포인터 입력 대상 최소 크기 24×24 CSS px
- 강화 기준의 입력 대상 크기는 44×44 CSS px
- 키보드 외에 터치·음성 같은 다양한 입력 방식은 폭넓은 사용자의 접근성을 높임

출처: [W3C, WCAG 2.2](https://www.w3.org/TR/WCAG22/), [W3C, 접근성 입력 방식 원칙](https://www.w3.org/WAI/fundamentals/accessibility-principles/)

### BITBOX 구현 매핑

| 고령층 장벽 | BITBOX 구현 | 차별성 설명 |
|---|---|---|
| 작은 글씨와 낮은 대비 | 큰 글씨·고대비 전환, 핵심 숫자 대형 표시 | 사용자가 화면 표시를 즉시 조정할 수 있음 |
| 작은 버튼과 손 떨림 | 주요 조작 버튼 44px 이상, 음성 버튼 약 80~96px | 정밀한 포인팅 부담을 줄임 |
| 키보드 입력 어려움 | 목적지 음성 입력 및 STT | 타이핑 없이 말로 검색 가능 |
| 긴 경로 설명을 읽기 어려움 | TTS 자동 안내, 다시 듣기·중지 | 텍스트와 음성을 동시에 제공 |
| 복잡한 메뉴와 정보 과부하 | 실시간 도착·목적지 검색 중심의 단일 과업 화면 | 탐색 단계와 인지 부담을 줄임 |
| 유사 지명으로 인한 오안내 | 장소 후보 확인 및 안전판정 | 확신이 낮을 때 임의로 경로를 안내하지 않음 |
| 승하차 부담 | 저상버스·비혼잡 차량 우선 보기 | 단순 최단 도착이 아닌 이동 편의 정보를 함께 고려 |
| 공용 키오스크 개인정보 잔존 | 음성 처리 사전 동의, 최근 목적지 제한, 90초 무활동 초기화 | 공용 환경의 개인정보 노출 위험을 줄임 |

구현 근거:

- `frontend/src/hooks/useAccessibilityDisplay.ts`: 큰 글씨·고대비 상태 관리
- `frontend/src/styles/index.css`: 큰 글씨 모드 120% 및 대비 강화
- `frontend/src/app/components/BusInfoList.tsx`: 큰 글씨, 저상·여유 우선, 대형 도착 정보
- `frontend/src/app/components/VoiceMicButton.tsx`: 대형 음성 입력 버튼
- `frontend/src/app/components/VoiceResult/index.tsx`: 음성 다시 듣기·중지
- `frontend/src/app/components/VoiceConfirmation.tsx`: 장소 후보 확인
- `frontend/src/app/components/VoiceAssistant.tsx`: 음성 동의 및 90초 세션 초기화
- `app/services/pipeline.py`: 불확실한 장소의 확인 절차와 안전한 실패 처리

## 4. 심사자료에 바로 사용할 차별성 문구

### 4.1 작품소개서용 요약문

BITBOX는 디지털 기기 사용에 어려움을 겪는 고령층을 위한 실시간 버스 안내 키오스크이다. 2025년 NIA 조사에서 70대 이상의 디지털 접근 수준은 90.7%였지만 조작 역량은 29.4%에 그쳤다. BITBOX는 이처럼 기기는 사용할 수 있으나 복잡한 조작이 어려운 사용자를 위해 큰 글씨·고대비 화면, 대형 버튼, 음성 목적지 검색, 음성 경로 안내를 제공한다. 또한 비슷한 역 이름은 사용자가 다시 확인하도록 하고 저상·비혼잡 버스를 우선 표시하여, 단순 정보 제공을 넘어 안전하고 이해하기 쉬운 이동 결정을 지원한다.

### 4.2 개발보고서용 문제정의

고령층의 디지털 격차는 단순한 기기 보유 여부만의 문제가 아니다. NIA의 2025년 조사에서 고령층의 디지털 접근 수준은 95.4%였지만 역량 수준은 56.2%였으며, 70대 이상은 접근 90.7%에 비해 역량이 29.4%로 크게 낮았다. 따라서 스마트폰 보급이나 앱 제공만으로는 대중교통 정보 접근 문제를 충분히 해결하기 어렵다. BITBOX는 복잡한 탐색·타이핑·작은 버튼을 최소화하고, 큰 글씨와 음성을 중심으로 실시간 버스 정보와 경로를 제공하도록 설계했다.

### 4.3 발표용 30초 멘트

“우리나라 65세 이상 인구는 이미 전체의 20%를 넘었습니다. 하지만 NIA 조사에서 70대 이상의 디지털 조작 역량은 일반국민 대비 29.4%에 불과합니다. 문제는 기기가 없는 것이 아니라, 작은 글씨와 복잡한 절차를 사용하기 어렵다는 점입니다. BITBOX는 큰 글씨, 큰 버튼, 음성 검색과 음성 안내, 그리고 잘못된 장소를 막는 재확인 절차를 하나로 묶어 고령층이 혼자서도 버스 정보를 확인할 수 있도록 설계했습니다.”

### 4.4 기대효과 문구

- 타이핑과 복잡한 메뉴 탐색을 줄여 고령층의 교통정보 접근 장벽 완화
- 시각과 청각을 함께 사용하는 다중감각 안내로 정보 이해 지원
- 유사 지명 재확인과 검증되지 않은 정보의 안내 거부를 통한 오안내 위험 완화
- 저상·비혼잡 차량 우선 정보 제공을 통한 승하차 편의 고려
- 공공 키오스크에서 스마트폰 앱 설치 없이 실시간 교통정보 접근 지원

## 5. 과장 없이 사용할 표현

### 사용 가능한 표현

- “공식 통계와 접근성 기준을 근거로 고령층의 이용 장벽을 고려해 설계했다.”
- “큰 글씨·대형 버튼·음성 입출력으로 조작 부담을 낮추도록 설계했다.”
- “장소가 불확실하면 임의 안내하지 않는 안전확인 절차를 구현했다.”
- “고령층의 독립적인 대중교통 정보 확인을 지원하는 것을 목표로 한다.”
- “시각·운동·인지 능력 변화를 함께 고려한 다중모달 인터페이스다.”

### 현재 사용하면 안 되는 표현

- “고령층 사용성이 입증됐다.”
- “고령층 만족도가 향상됐다.”
- “교통사고나 길찾기 실패를 몇 퍼센트 감소시켰다.”
- “국내 최초” 또는 “유일한 서비스”
- “WCAG 2.2 완전 준수” 또는 “접근성 인증 완료”

실제 사용자 시험이나 공인 접근성 심사를 하지 않았으므로, 현 단계에서는 **입증·감소·인증** 대신 **고려·설계·지원·목표**라는 표현을 사용한다.

## 6. 현재 구현의 정직한 한계와 보강 계획

### 현재 한계

- 고령층 대상 직접 사용성 시험을 수행하지 못했다.
- 큰 글씨 모드는 현재 기본 글자 대비 120% 확대다. WCAG의 200% 기준은 사용자가 200%까지 확대해도 콘텐츠와 기능이 손실되지 않아야 한다는 기준이므로, 현재 버튼 하나만으로 WCAG 2.2 준수를 주장해서는 안 된다.
- 실제 정류장 키오스크 환경의 조도·소음·화면 크기·터치 오차를 반영한 현장시험은 아직 없다.

### 향후 검증 계획으로 제시할 항목

- 65세 이상 사용자 5~10명 대상 과업 수행 시험
- 측정 과업: “도착 버스 확인”, “목적지 음성 검색”, “장소 후보 선택”, “음성 다시 듣기”
- 지표: 과업 성공률, 완료 시간, 잘못 누른 횟수, 도움 요청 횟수, 음성 재시도 횟수, 5점 만족도
- 기본 화면과 큰 글씨·음성 모드 간 비교
- 정류장 소음 조건에서의 음성 인식과 재확인 성공 여부 확인

사용자 시험을 하지 못한 경우에는 위 내용을 “향후 검증 계획”으로 제시하고, 이미 수행한 자동화 테스트와 실제 API 시연은 기술 신뢰성 근거로 별도 제시한다.

## 7. 발표 슬라이드 구성 권장안

1. **문제**: 초고령사회와 디지털 조작 역량 격차
2. **근거**: 65세 이상 20.3%, 70대 이상 디지털 역량 29.4%
3. **기존 장벽**: 작은 글씨, 복잡한 단계, 타이핑, 유사 지명 오안내
4. **해결**: 큰 글씨·큰 버튼·음성 입출력·단일 과업 흐름
5. **고령친화 교통 기능**: 저상·비혼잡 우선, 실시간 도착, 음성 경로 안내
6. **안전 설계**: 장소 재확인, 데이터 불확실 시 안내 거부
7. **신뢰성**: 실제 Kakao·ODsay·서울 버스·OpenAI 연동 및 자동화 테스트
8. **한계와 계획**: 고령층 현장시험을 향후 검증 과제로 명시
