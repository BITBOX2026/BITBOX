# BITBOX 실증 평가 및 발표 운영 지침

이 문서는 수상 또는 배포를 위해 결과를 과장하지 않고 BITBOX의 효과와 안전성을
측정하는 절차를 정의한다. 참가자가 없는 상태에서 성공률, 만족도 또는 개선율을
작성하지 않는다. 합성 음성 결과는 실제 사용자 결과로 표시하지 않는다.

## 1. 평가 질문

1. BITBOX가 비교 대상 지도 앱보다 버스 조회 과업을 더 적은 시간과 조작으로 완료하게 하는가?
2. 실제 발화에서 버스 번호와 목적지를 얼마나 정확하게 인식하는가?
3. 잘못 인식한 버스 번호를 정상 노선으로 안내하는 위험한 오안내가 발생하는가?
4. 모호한 장소, 마이크 거부, 무음 및 외부 API 장애에서 사용자가 안전하게 복구하는가?

## 2. 사용자 과업 평가

최소 5명, 권장 10명 이상의 자발적 참가자를 모집한다. 교통약자 대상 효과를 주장하려면
해당 사용자 집단을 실제로 포함해야 한다. 동의 없이 음성, 이름 또는 건강 정보를 수집하지 않는다.

각 참가자는 BITBOX와 비교 대상 앱에서 다음 과업을 수행한다.

- 지정 정류장의 3412번 도착 정보 확인
- “강남역” 목적지 검색 후 2호선 후보 확인
- 존재하지 않는 3423번 질의 후 재확인 절차 수행
- 마이크 권한 거부 후 텍스트 검색으로 복구

학습 순서 편향을 줄이기 위해 참가자 절반은 BITBOX부터, 나머지는 비교 앱부터 수행한다.
관찰자는 성공 여부, 완료 시간, 터치 수, 재시도 수만 기록한다. 실패 사례도 삭제하지 않는다.

템플릿을 개인 저장 공간으로 복사한다.

```powershell
New-Item -ItemType Directory -Force evaluation-results
Copy-Item docs/evaluation/user-study-template.csv evaluation-results/user-study.csv
```

실측 후 다음 명령으로 전체 기술통계와 동일 참가자·동일 과업의 대응 비교를 생성한다.

```powershell
python scripts/analyze_user_study.py evaluation-results/user-study.csv `
  --output evaluation-results/user-study-report.json
```

보고서의 개선율은 표본의 기술통계일 뿐이다. 적절한 표본설계와 통계 검정 없이
“통계적으로 유의하다” 또는 전체 고령자에게 일반화된다고 주장하지 않는다.

## 3. 실제 음성 벤치마크

조용한 실내, 버스 정류장 소음, 작은 목소리, 빠른 발화 조건을 구분한다. 고령자 성능을
주장하려면 실제 고령 참가자의 동의를 받은 샘플이 필요하다. 녹음은 `voice-samples/`에만
보관하며 Git에 커밋하지 않는다.

```powershell
New-Item -ItemType Directory -Force voice-samples,evaluation-results
Copy-Item docs/evaluation/voice-sample-manifest-template.csv `
  evaluation-results/voice-sample-manifest.csv
python scripts/voice_benchmark.py evaluation-results/voice-sample-manifest.csv `
  --output evaluation-results/voice-report.json `
  --max-dangerous-substitutions 0
```

보고서에는 음성 원본과 전사문이 포함되지 않는다. 발표 핵심 지표는 다음과 같다.

- 버스 번호 정확 일치율
- 의도 정확도
- 예상 복구 행동 일치율
- 위험한 번호 대체 건수

목표 수치는 실측 전에 결과처럼 표시하지 않는다. `0건` 목표와 실제 `0건` 결과를 구분한다.

## 4. 접근성 현장 점검

- Windows NVDA와 iOS VoiceOver에서 장소 확인 다이얼로그 제목 및 기본 후보가 읽히는지 확인
- 키보드만으로 검색, 후보 선택, 질문 다시 듣기, 재시도 수행
- 200% 확대에서 가로 스크롤과 버튼 잘림 확인
- 실제 스마트폰에서 마이크 허용, 거부, 무음, 20초 자동 종료 확인
- 음성 자동 재생 차단 시 재생 버튼으로 복구되는지 확인

자동화된 ARIA 및 포커스 테스트는 실제 스크린리더 사용성 평가를 대신하지 않는다.

## 5. 장애·부하 검증

무과금 상태 엔드포인트 부하는 다음과 같이 측정한다.

```powershell
python scripts/load_smoke.py --url https://<domain>/health `
  --requests 500 --concurrency 50 --max-error-rate 0.01 --max-p95-ms 1000 `
  --output evaluation-results/load-report.json
```

운영 서버에서 외부 API 회로를 의도적으로 열어 검증할 때는 실제 사용자가 없는 점검 시간에
실시한다. `/health`는 프로세스 생존을, `/ready`는 외부 서비스를 포함한 요청 처리 가능 상태를
나타내야 한다. `/ready` 503, 사용자 오류 안내, 회로 복구 후 200 전환을 모두 기록한다.

유료 음성·경로 API에 부하 테스트를 수행하지 않는다. 제공자 쿼터와 비용 한도를 먼저 설정하고,
필요하면 승인된 별도 스테이징 계정을 사용한다.

## 6. 시연 순서와 실패 대비

1. 3412번 도착 조회와 “검증 절차 완료” 근거 표시
2. 3423번 조회에서 유사 번호로 바꾸지 않는 재확인
3. “강남역”의 2호선 우선 후보와 신분당선 대안 확인
4. 후보 확정 후 버스 경로와 지도 표시
5. 네트워크 장애 또는 자동 재생 차단 복구 화면

현장 네트워크 실패에 대비해 동일 흐름의 2~3분 녹화본을 준비한다. 녹화본 사용 시 실시간
시연이라고 말하지 않는다. 발표 자료에는 테스트 날짜, 기기, 브라우저, 표본 수와 실패 건수를 함께 적는다.

## 7. 발표에서 허용되는 표현

- “백엔드 테스트 N개를 통과했다” — N을 발표 직전 실행 결과에서 그대로 옮겨 적을 때.
  숫자는 테스트가 늘면 함께 바뀌므로 이 문서에 고정해 두지 않는다.
  (`python -m pytest -q` 마지막 줄이 그날의 N이다.)
- “실제 API 연동을 확인했다” — 호출 날짜와 시나리오 기록이 있을 때
- “위험한 오안내율 0%” — 실제 표본 수와 조건을 함께 제시할 때

다음 표현은 근거 없이 사용하지 않는다.

- “모든 고령자가 사용할 수 있다”
- “100% 정확하다”
- “네이버지도보다 우수하다”
- “장애가 절대 발생하지 않는다”
